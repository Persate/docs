**WORKSPACE → Repository** contains files owned by the current user and files shared through the user's groups. Repository access must be enabled for the organization.

## What Repository provides

* Local upload for PDF, DOCX, XLSX, and CSV files.
* Private or selected-group access for each file.
* List and tile views with search, filters, sorting, preview, and metadata.
* Single and batch download.
* Single and batch deletion.
* Source material for the main Advisor and other entitled workflows.
* [Google Drive and Microsoft OneDrive connections](/repository/cloud-integrations).
* [Smart Folders](/repository/smart-folders) that collect files by semantic and technical criteria.

Repository is not a traditional folder tree. File audience controls access; Smart Folders are saved matching rules and do not move or duplicate the underlying files.

## Access model

Every Repository file has one audience:

* **Only me** — the owner only;
* selected groups — current members of those groups.

The owner or an authorized administrator can update the audience later. Removing a group from a file stops access through that group but does not delete the file.

## Processing status

Files appear in the list after a successful upload. Content extraction, summary generation, language detection, and search indexing continue in the background. Features that depend on extracted text remain unavailable until processing reaches the required state.

## Empty and access states

* **No files found** — the Repository is empty or current search and filters exclude every visible file.
* Processing or summary not ready — the upload succeeded but analysis has not completed.
* Preview unavailable — download the original and confirm that the browser supports the format.
* Feature locked — Repository is not enabled for the organization.
