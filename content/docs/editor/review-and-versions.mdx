---
title: Review and versions
description: Checking facts and language with Check document, resolving review points, and working with document history and saved reviews.
---

**Check document** reviews the article passage by passage and marks its findings in the text. Before each check, Editor saves a snapshot of the article, which **History** keeps as a saved review.

## Run a check

1. In the toolbar, open **More formatting** (**…**) → **Review options** and choose the modules:
   * **Facts & sources** — checks factual statements and links the evidence found for them;
   * **Language & clarity** — suggests corrections of grammar and typos, clarity, precision and style.
2. Select **Check document**.

Both modules are selected by default, and the selection is remembered for later checks. **Check document** is unavailable when no module is selected and for documents longer than 60,000 characters (**Up to 60,000 characters per check.**). The article is saved before the check starts.

During the check, the document is read-only and a status line above the text shows the stage — for example **Building context**, **Mapping statements**, **Checking facts · 3/12** or **Reviewing language**. Points appear in the text as they are produced. **Stop checking** ends the check; points already returned remain. If the page is reloaded or the connection drops, Editor reconnects to the running check.

When a check does not finish, the status line says so, for example **The check did not finish. Retry from the toolbar menu.** Run **Check document** again.

## Read review points

Each point marks a passage with a colored underline and a number in the right margin; the numbers are hidden when the document area is narrow. Numbering follows the order of the text.

| Result | Color |
| :--- | :--- |
| **Confirmed** | blue |
| **Contradicted**, **Potentially misleading** | red |
| **Unverified** | grey |
| Language suggestion (grammar or typo, clarity, precision, style) | red |
| Applied change | green |

Hovering a passage shows the point's summary, and faint lines connect it with related points — nearby or about the same subject. Selecting the passage or its number opens quick actions: the proposed change (**Before** and **After**), **Apply suggestion**, **Undo change** for an applied point, and **Explanation**.

**Explanation** opens the finding in the side panel with its label, summary, the quoted passage, the reasoning, the proposed change and — for **Facts & sources** — links to the sources used. The label gives the result (**Confirmed**, **Contradicted**, **Potentially misleading**, **Unverified** or **Suggested improvement**) or the point's state (**Applied**, **Dismissed** or **Changed manually**). **Could not review** marks a passage the check could not assess.

Labels support editorial judgment but do not replace it. Before publishing, open the sources and compare them with the exact wording of the claim.

## Resolve a point

Points can be resolved once the check has finished. In the side panel:

* **Apply** replaces the passage with the proposed text; it is available only when the point proposes one.
* **Dismiss** keeps the passage unchanged and marks the point **Dismissed**.
* **Restore** reopens an applied or dismissed point; for an applied point, the original wording returns.

Decisions are saved immediately. Editing a passage that has an open point by hand marks the point **Changed manually**. Dismissed and manually changed points no longer mark the text, and the remaining points are renumbered.

## Document history

**History** in the rail opens **Document history**:

* **Current draft** — **Continue writing →** returns to the text.
* **Changes since the latest review** — what changed in the text since the most recent saved review, before and after.
* **Recent changes** — the 50 most recent changes: typing, formatting, title changes, applied review points and applied Advisor changes. Each entry shows the author (**You** or **Advisor · Applied by you**), the time and the text before and after; consecutive typing is grouped into one entry. Edits made before this list was introduced were not recorded.
* **Document origin** — how the article started (**Original document**, **Document imported by you** with the file name, or **Draft created by Advisor**), when it was created and the beginning of the original text.
* **Saved reviews** — the snapshot taken before each check, newest first. Snapshots are numbered in the order they were taken (**Review 1** is the oldest) and show the modules, the time, the check status (for example **Complete**, **Partially complete**, **Stopped**, **Failed** or **Interrupted**) and the difference from the preceding snapshot. Before the first check, the list shows **No previous reviews**.

## Open or restore a saved review

Selecting a saved review opens its snapshot read-only, with **Viewing a saved review** above the text. Unsaved changes in the current draft are saved first. Review points are not shown on a snapshot, and Advisor is unavailable while it is displayed.

* **Return to current draft** goes back to the current text.
* **Restore this version** replaces the current draft with the snapshot at once, without a confirmation step, and clears the review points of the current draft. To keep the current wording, copy it with **Copy text** before opening the snapshot.
