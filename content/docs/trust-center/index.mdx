This page summarizes the protections and privacy controls available when using Persate. Detailed security information for an organization's assessment should be requested through its agreed support channel.

## Account protection

Sign-in uses a password or an identity provider available on the sign-in page. Two-step verification adds a code from an authenticator app. It is required for company-file information and uploads; enrolled accounts continue to verify sign-in, with support for trusted browsers. System administrators must configure two-step verification before entering the platform.

**Settings → Security & Privacy** provides active sessions, trusted browsers and login history. An unfamiliar session can be ended, and trust in a browser can be revoked. Sensitive actions may require fresh verification. See [Security and privacy](/account-and-settings/security).

## Access to organization data

Access depends on the signed-in account, organization membership, role, groups and permissions for the particular resource. An organization role does not automatically grant access to every file or conversation.

Advisor conversations are private by default. Moving one into a shared project requires the author's confirmation and makes the entire conversation and saved analysis readable by the project's members. Access to cited materials is checked separately. See [Conversation history and sharing](/advisor/conversations#conversation-history).

Review the selected audience before sharing files, alerts or conversations. Content copied or exported outside Persate must be handled according to the organization's own rules.

## Connections and connected applications

Connections to the public Persate application use HTTPS. Account sessions and connected AI applications can be reviewed and managed in Settings.

An external AI application receives only the access allowed by the organization and approved by the user. Disconnect an application when it is no longer needed or its access is not recognized. See [MCP and AI apps](/account-and-settings/mcp).

## External processing and privacy

Some functions use external processing. **Settings → Organization → External providers** describes the purpose, data shared and consequences of changing each permission. Administrators control these permissions; members can review them. See [Administration](/administration).

Before submitting confidential material, check the organization's permissions and applicable data-handling rules. Disabling a permission can prevent new work that depends on it; work already processing may finish.

## Personal data and security questions

**Settings → Security & Privacy** offers an export of personal account data and browser-specific analytics controls. File contents are downloaded through the Repository. Requests outside the available controls, including account deletion, should use the organization's agreed support channel.

For a security or procurement review, request the current information on data location, processing terms, retention and relevant security measures through that channel. This overview does not replace the documentation agreed for the organization.
