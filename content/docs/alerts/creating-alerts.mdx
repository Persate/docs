---
title: Create and edit alerts
description: Build a reviewable monitoring rule, set its audience and sensitivity, and save it safely.
---

Open **CORE → Tracker** and select **Create alert**.

## Describe the monitoring objective

Under **What do you want to monitor?**, describe the exact subject and the change or evidence that should count. Include distinguishing names, identifiers, jurisdiction, and exclusions when they matter.

The mention search can bind the alert to an exact person, organization, RCL project, or other supported object. Prefer an exact result over plain text when similarly named entities could be confused.

Persate researches the request and builds a draft containing the name, description, keywords or entities, structured intent, and source scope. It can ask for clarification. You can stop a running creation; completed draft progress remains available when the backend has saved it.

## Review before saving

Check the generated draft for:

* the exact person, organization, project, question, or topic;
* conditions that should create a match;
* exclusions and context-only entities;
* supported sources in the proposed scope;
* overlap with an existing alert.

Use the refinement input to request a correction. If Persate flags an unsupported condition, change the definition before saving instead of assuming that the label will be monitored.

## Audience and sensitivity

Choose **Only me** or selected groups. At least one group is required for shared access. Selected groups can open the alert; eligible recipients receive notifications only through delivery channels enabled in their own preferences.

Choose the match sensitivity appropriate to the workflow:

* **Precise** — narrower main matches;
* **Balanced** — main matches plus lower-confidence near misses;
* **Broad** — wider capture with more review noise.

Review the preview, then select **Save** or **Create alert** as shown. A successful save opens the alert detail. Do not navigate away while the final save is running.

## Drafts and edits

Interrupted saved work appears under **Drafts** and can be resumed or discarded. If a draft is no longer accessible, it may have been deleted or hidden by tenant access controls.

From an alert detail, **Edit** opens the same review-oriented flow with the existing definition. Access information must load before Persate permits editing, so a stale or partial alert cannot silently overwrite its audience.

## Troubleshooting

* No exact object found — broaden the mention search, confirm the identifier, or use a well-scoped topic description.
* Unsupported condition — refine the rule to a capability the creator confirms.
* **Choose at least one group, or select Only me** — complete the audience before saving.
* Save did not complete — remain on the page, retry once, and confirm that no alert was created before starting over.
