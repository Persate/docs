## Screen layout

The conversation fills the center of the screen and the message composer sits at the bottom. The right edge of the screen holds the Advisor controls:

* **Conversations** — shows or hides the list of conversations. The browser remembers the choice.
* **Plan** — appears when the current answer has a plan; opens it in place of the conversation list. See [Following the Advisor's work](/advisor/activity).
* **Research agents** — one icon per research agent of the conversation; each opens that agent's session beside the chat.

On narrow screens, **New conversation** and **History** buttons sit in the top right corner and shrink to icons once a conversation has started. History opens as a panel from the bottom of the screen; a list button opens the plan when one exists.

## Starting a conversation

An empty conversation shows a greeting and the question *"Can I help you with anything?"*. Ready-made starting points are available:

* **Topic suggestions** — the lightbulb button (**Show topic suggestions**) at the start of the field, or selecting the empty field, opens a list of recent developments from the platform's sources, each marked with an icon of its subject area. The button is shown only in a new conversation when suggestions are available.
* **Alert tip** — when an alert has recently found a match, it appears first in the list, with the alert name in blue and an **Open alert** link to the alert detail.

Selecting a suggestion fills the field with a draft question — *Investigate “…”. What do the sources confirm, and why does it matter?*, prefixed with *For alert “…”:* for an alert tip — and attaches the source as a context tag. The draft can be edited before sending.

A question can also be sent from the platform search: a query phrased as a question offers **Ask the Advisor**, which opens a new conversation and sends the question.

## Composing a message

The field (*Type a message...*) expands when selected and shows the message tools:

* **Enter** sends the message; **Shift + Enter** starts a new line.
* **Thinking depth** — the depth control (**Surface**, **Balanced**, **Deep**) applies to this message only. See [Thinking depth](/advisor#thinking-depth).
* **Add context from global search** — the button with the Repository icon opens the platform search. Typing `@` opens the same search; the character is not inserted into the text.
* **Send message** — inactive when the field is empty or while the Advisor is working on the previous question.

While the Advisor works, the send button is joined by a stop button (**Stop research**), and text typed in the field is sent as a note to the running task rather than as a new question. See [Following the Advisor's work](/advisor/activity).

## Attaching context

The platform search opened from the composer covers the same areas as the global search. Results are picked one after another and stay highlighted; selecting a highlighted result again removes it.

* **Files** from the Repository appear above the field as previews.
* **Other results** — for example a vote, a Sejm print, a profile or a recording — appear as context tags with their source icon. The source tag added by a topic suggestion opens that material in a new tab.
* The **×** on a preview or tag removes it from the message.

Several items can be attached to one message, and a message may consist of attachments alone. Attach material when it contains the answer; when the location of the information is unknown, let the Advisor search on its own.

## Reading the answer

The answer appears under the activity summary (*Worked for …*), which can be expanded to show the work behind it. References in the answer are **citation chips** — a source icon with a title. Selecting a chip opens the source:

* Votes, acts, prints, RCL projects, parliamentary questions, profiles, committees, alerts, Media events and stories, recordings and earlier conversations open in the platform.
* Posts on X, web pages and the official Sejm stenogram open in a new tab.
* Legislative chips also show a short excerpt of the cited passage; Media event chips show the account and the post text.

Citations point to the exact passage where one is available:

* A cited file opens in the file viewer with the **Cited passage** shown alongside the document.
* A cited passage of a legal text opens the document reader at that passage.
* A cited Sejm print opens its document; when the print contains several documents, a list asks which one to read.
* A cited transcript passage opens on a separate page with the **Original source passage**.

If the exact passage cannot be opened, a message says so; in the file viewer the document itself stays open. The complete list of citation types is in [Advisor skills](/advisor/skills#citation-uris).

## Answer controls

Icons below every completed answer:

* **Shield** — appears when the answer has a source check. Hovering shows the result; selecting the shield opens the details. See below.
* **Copy response** — copies the answer text to the clipboard.
* **Regenerate response** — runs the same question again and replaces this answer.

The shield's color deepens as more of the key points are confirmed; it is red when the check could not be completed. Possible results:

| Result | Meaning |
| :--- | :--- |
| **Key points supported by sources** | The key answer points match the collected sources. |
| **Some key points need caution** | Only the points that need clarification are listed in the details. |
| **Answer reviewed** | The answer was reviewed in the context of the question and the available sources. |
| **Answer reviewed with limitations** | As above, with limitations listed in the details. |
| **Confirmed by live workspace read** | The answer comes directly from the workspace's live data, read during this turn. |
| **Answer not verified** | The answer was not checked against sources. |
| **Verification unavailable** | The independent source check could not be completed. |

The details list **Relevant cautions** — a few passages not confirmed by the sources, each with a reason — and, after a failed check, a hint to repeat or narrow the question.

## Drafts in other modules

On request, the Advisor prepares work that is finished in another module. A card below the answer opens the draft:

| Card | Destination | Statuses |
| :--- | :--- | :--- |
| **Monitoring setup** (or the alert name) | Tracker | **Setup required · Monitoring is not active** |
| **Article draft** (or the article title) | Editor | **Preparing draft**, **Draft saved**, **Needs review · Your edits are preserved**, **Preparation interrupted** |

If the conversation is still open when an alert draft or an article draft is ready, Persate opens the destination automatically; the card opens it again later. Alert drafts stay inactive until they are reviewed and saved in the Tracker, and article drafts are never published by the Advisor. The destination shows the research behind the draft and a link back to the original conversation.

A request to create a Smart Folder or to explore connections between people and organizations produces a card that opens the Smart Folders creator or the **Connections** tab of Stakeholders with the request filled in.

The Editor is available when it is enabled for the organization. See [Creating and editing alerts](/alerts/creating-alerts), [Editor](/editor), [Smart Folders](/repository/smart-folders) and [Connections](/stakeholders/connections).

## Conversation history

The conversation list shows the account's conversations, newest first:

* **New conversation** — clears the workspace and starts a new session.
* **Search conversations** — the magnifier beside **New conversation** opens a search field; the cross or Escape closes it and clears the query.
* **Show more** — loads older conversations at the end of the list.
* Selecting a conversation opens it with the full record — activity, citations and cards are reconstructed. The page address identifies the open conversation, so a refresh keeps it open.
* **Delete conversation** — the trash icon next to an entry deletes the conversation permanently. There is no confirmation step.

A conversation without a title is listed as **New conversation**. Sessions held in the Editor's Advisor panel do not appear in this list.

Messages:

* *"No history yet"* — the account has no conversations.
* *"No conversations found"* — nothing matches the search; try a different term.
* *"Could not load conversations"* — the list could not be loaded; refresh the page.

## Long conversations

Older messages load when the conversation is scrolled to the top. From the second question onwards, a thin rail of markers appears at the left of the conversation, one marker per question. Hovering a marker shows the question and the start of its answer; selecting it scrolls to that point.

## Refresh and resume

A running task is not lost when the view is closed, the browser is refreshed or the connection drops for a moment — the Advisor continues in the background. Reopening the conversation in the same browser reconnects to the task and restores the progress so far.

When a conversation is left while the Advisor is still working, a notification arrives once the task finishes, provided **Advisor notifications** are enabled in **Settings → Notifications**. Returning to the conversation before the task finishes withdraws that request.

Stopped tasks, partial answers and connection problems are described in [Following the Advisor's work](/advisor/activity#interruptions-and-partial-answers).
