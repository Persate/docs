The **Advisor** is Persate's analytical assistant for research across the platform's public data and the organization's own documents. It is not a free-form chatbot: it answers by running searches through the platform's MCP layer, and every reference in an answer is a citation that opens the source.

Open the Advisor from **CORE → Advisor** in the sidebar. The entry is shown when the Advisor is enabled for the organization.

## Scope of applications

The Advisor automates research that would otherwise require searching several modules by hand:

* **Correlational search** — linking records kept in different modules. Example: *"Which committee handled the latest energy prices bill, and how did each club vote on it?"*
* **Multi-source synthesis** — setting statements against records. Example: *"Compare the club's public statements on phasing out coal with its voting record over the last six months."*
* **Work with the organization's files** — reading, summarizing and comparing Repository documents and checking them against public records.
* **Preparing work in other modules** — on request, an alert draft for the Tracker, a Smart Folder, or an article draft for the Editor. The Advisor never activates or publishes anything; drafts are reviewed and completed in the destination module.

**Note:** The Advisor is not intended for general conversation, creative writing, code or forecasts unrelated to the platform's data.

## Key system features

* **Grounded answers** — every answer is based on searches run during the turn; the work is visible above the answer.
* **Interactive citations** — claims carry source chips that open the vote, profile, document passage, recording moment or post.
* **Visible work** — reasoning, tool calls, the plan and research agents appear while the Advisor works and fold into a single line when it finishes.
* **Source check** — many answers carry a shield icon that summarizes whether the key points are supported by sources.
* **Collaboration while it works** — a note can be added to a running task, and the task can be stopped at any time.

## Areas of competence

The Advisor's tools are grouped into **skill families**, each a namespace of the MCP layer (for example `legislation`, `civic`, `stakeholders`, `public_pulse`, `recordings`, `documents`, `alerts`, `chat_context`). The tools available depend on the modules enabled for the organization.

| Area | Analysis scope |
| :--- | :--- |
| **Legislation and votes** | Sejm and Senate votes, legislative processes and RCL projects, Sejm prints, published legal acts, parliamentary questions, committees, presidential decisions and Constitutional Tribunal cases. |
| **Stakeholders** | Profiles of politicians and organizations, club membership, constituency, voting attendance and activity. |
| **Recordings** | Analyzed recordings of sittings and committees: summaries, transcripts and speeches. |
| **Media** | Archived X posts of tracked accounts, plus the events, stories and topics of the Media module. |
| **Documents** | Repository files and the public Persate corpus. |
| **Tracker** | The user's alerts and their matches; alert drafts on request. |
| **Web** | Public web pages, when a question calls for them. |
| **Conversations** | The user's earlier Advisor conversations. |

The families, typical questions and citation types are described in [Advisor skills](/advisor/skills).

## Thinking depth

The depth control in the composer sets how thoroughly the Advisor works on a message:

* **Surface** — fast, direct references only; suited to lookups and short follow-ups.
* **Balanced** — the standard setting, recommended for most questions.
* **Deep** — the most thorough option, for multi-source briefings and comparisons.

The choice applies to one message. After sending, the control returns to the default. Guidance on choosing a depth is provided in [Best practices](/advisor/best-practices).

## Conversation history

The list of conversations sits on the right; the **Conversations** control on the right edge shows or hides it. Each conversation is listed under a title derived from its opening question.

* **New conversation** — clears the workspace.
* **Search conversations** — filters the list.
* **Resuming** — selecting an entry restores the full record, including the activity and citations.
* **Deleting** — the trash icon permanently deletes the conversation without a confirmation step.

Conversation history belongs to the individual account and is not shared within the organization.

## Workflow continuity

A running task is not interrupted when the view is closed or the browser is refreshed — the Advisor continues in the background. Reopening the conversation in the same browser reconnects to it and restores the progress so far. When **Advisor notifications** are enabled in [Settings → Notifications](/account-and-settings/preferences), a notification arrives when a task left in the background finishes.

## Other entry points

* **Global search** — a query phrased as a question offers **Ask the Advisor**, which starts a new conversation with that question. See [Search and notifications](/using-persate/search-and-notifications).
* **Editor** — the Editor has its own Advisor panel for the article being written; those sessions do not appear in the Advisor history. See [Editor](/editor).
* **Labs** — some labs include a separate **Lab Advisor**. See [Labs](/labs).

## Availability and organization settings

* Administrators allow or block the external processing the Advisor relies on in **Settings → Organization → External providers**. While it is blocked, the Advisor cannot start new work; existing conversations are kept. See [Administration](/administration).
